📍 GIAI ĐOẠN 1: KHỞI TẠO & PHÂN TÍCH YÊU CẦU (TUẦN 1)
Nguyên tắc Waterfall: Không mở trình duyệt lên code khi chưa có tài liệu.
1. Hành động cụ thể:
Viết tài liệu SRS (Software Requirements Specification): Tạo file Google Docs dùng chung. Ghi chép rõ ràng tính năng nào SẼ LÀM (In-scope) và KHÔNG LÀM (Out-of-scope).
Vẽ Biểu đồ Use Case: Sử dụng draw.io (diagrams.net) để phác thảo các tình huống sử dụng:
Khách hàng: Đăng nhập, Xem danh sách sách, Xem chi tiết, Thêm giỏ hàng, Thanh toán COD.
Admin: Đăng nhập, Quản lý sách (CRUD), Quản lý danh mục, Quản lý đơn hàng.
2. Phân vai thực thi:
Cả 5 thành viên cùng họp mặt, bàn bạc và "chốt sổ" các luồng nghiệp vụ (Ví dụ: Khách chưa đăng nhập thì có được xem giỏ hàng không?). Thư ký nhóm ghi chú trực tiếp vào file SRS.

📍 GIAI ĐOẠN 2: THIẾT KẾ HỆ THỐNG (TUẦN 2)
Chuyển ngữ từ yêu cầu văn bản sang bản vẽ kỹ thuật.
1. Hành động cụ thể:
Thiết kế Database (ERD): Vẽ sơ đồ thực thể liên kết cho các bảng cốt lõi: Users, Categories, Books, Orders, Order_Details. Xác định rõ Khóa chính (PK) và Khóa ngoại (FK). Sau đó, xuất ra file database_init.sql.
Thiết kế Giao diện (UI/UX): Phác thảo Wireframe trên Figma (hoặc giấy) cho các trang quan trọng: Trang chủ, Chi tiết sản phẩm, Giỏ hàng, Bảng điều khiển Admin. Xác định bố cục và màu chủ đạo.
Thiết kế Kiến trúc: Thống nhất áp dụng mô hình MVC (Model - View - Controller).
2. Phân vai thực thi:
Team Front-end (2 người): Tìm kiếm và tùy biến template HTML/CSS/Bootstrap có sẵn cho giống layout Fahasa.
Team Database (3 người): Dựng ERD, chạy file SQL tạo bảng thực tế trong MySQL, và chèn (insert) khoảng 20-30 dòng dữ liệu mẫu (sách, danh mục).

Mô hình Kiến trúc: MVC (Model - View - Controller)
Công nghệ: Java Core, Java Servlet/JSP, JDBC, MySQL, HTML/CSS/Bootstrap
1. Giới thiệu (Introduction)
Mục đích tài liệu: Tài liệu này cung cấp mô tả chi tiết về các yêu cầu chức năng và phi chức năng cho dự án ứng dụng web "Mini Fahasa". Tài liệu đóng vai trò là cơ sở để thiết kế cơ sở dữ liệu, phân chia công việc lập trình và xây dựng các kịch bản kiểm thử (test cases) cho nhóm phát triển gồm 5 sinh viên.
Phạm vi dự án: Dự án tập trung xây dựng một hệ thống thương mại điện tử cốt lõi trong thời gian 2 tháng. Các tính năng nằm trong phạm vi (In-scope) bao gồm: duyệt sản phẩm, quản lý giỏ hàng, thanh toán khi nhận hàng (COD) cho khách hàng, và các chức năng quản lý kho sách, danh mục, đơn hàng cơ bản dành cho quản trị viên.

Đối tượng người dùng (User classes):
Khách hàng (Customer): Bao gồm khách vãng lai và thành viên đã đăng ký. Họ sử dụng hệ thống để tìm kiếm sách, xem chi tiết, thêm vào giỏ hàng và tiến hành đặt hàng.
Quản trị viên (Admin): Nhân sự có quyền truy cập vào hệ thống nội bộ (trang Admin) để thêm/sửa/xóa sách, danh mục sách và cập nhật trạng thái xử lý của các đơn hàng.

4. Yêu cầu phi chức năng (Non-functional Requirements)
Hiệu suất (Performance): Thời gian tải trang (Page load time) của các thao tác truy vấn dữ liệu thông thường không được vượt quá 3 giây. Việc phân trang (Pagination) cần giới hạn số lượng sách tải mỗi trang (ví dụ: 12-16 cuốn/trang) để tối ưu hiệu suất truy vấn.
Bảo mật (Security): Mật khẩu người dùng tuyệt đối không được lưu dưới dạng plain-text (văn bản thuần) mà phải được băm (Hashing) cơ bản (ví dụ sử dụng BCrypt hoặc SHA-256) trước khi đưa vào CSDL. Sử dụng PreparedStatement trong JDBC để ngăn chặn lỗi bảo mật SQL Injection.
Tính dễ sử dụng (Usability): Giao diện (UI) cần gọn gàng, có khả năng đáp ứng cơ bản trên các kích thước màn hình máy tính (sử dụng Grid system của Bootstrap). Các form nhập liệu phải có tính năng validate cơ bản (không để trống, đúng định dạng số, email) để báo lỗi rõ ràng cho người dùng.
5. Ràng buộc cơ sở dữ liệu (Database Constraints)
Để hỗ trợ kiến trúc MVC và phục vụ đầy đủ các chức năng trên, cấu trúc Cơ sở dữ liệu quan hệ (MySQL) nên bao gồm các bảng cốt lõi với khóa chính (PK) và khóa ngoại (FK) như sau:
Bảng Users (Người dùng):
User_ID (INT, Tự tăng) - PK
Username, Password_Hash, Email, FullName, Address, Phone
Role (INT hoặc VARCHAR: để phân biệt Admin và Customer)
Bảng Categories (Danh mục):
Category_ID (INT, Tự tăng) - PK
Category_Name
Bảng Books (Sách):
Book_ID (INT, Tự tăng) - PK
Title, Author, Price, Description, Stock_Quantity, Image_URL
Category_ID (INT) - FK liên kết với bảng Categories
Bảng Orders (Đơn hàng):
Order_ID (INT, Tự tăng) - PK
User_ID (INT) - FK liên kết với bảng Users
Order_Date, Total_Amount, Status (Pending/Shipping/Delivered)
Shipping_Address, Shipping_Phone
Bảng Order_Details (Chi tiết đơn hàng):
Detail_ID (INT, Tự tăng) - PK
Order_ID (INT) - FK liên kết với bảng Orders
Book_ID (INT) - FK liên kết với bảng Books
Quantity, Unit_Price

-- ==============================================
-- 1. BẢNG ĐỘC LẬP (Không tham chiếu khóa ngoại)
-- ==============================================
CREATE TABLE Roles (
    Id INT PRIMARY KEY IDENTITY(1,1),
    Name NVARCHAR(50),
    Description NVARCHAR(255)
);

CREATE TABLE Categories (
    Id INT PRIMARY KEY IDENTITY(1,1),
    ParentId INT FOREIGN KEY REFERENCES Categories(Id),
    Name NVARCHAR(100)
);

CREATE TABLE Suppliers (
    Id INT PRIMARY KEY IDENTITY(1,1),
    Name NVARCHAR(255),
    ContactEmail NVARCHAR(100),
    ContactPhone NVARCHAR(20),
    Address NVARCHAR(MAX)
);

CREATE TABLE Discounts (
    Id INT PRIMARY KEY IDENTITY(1,1),
    Code NVARCHAR(50),
    DiscountPercent DECIMAL(5,2),
    MaxDiscountAmount DECIMAL(18,2),
    StartDate DATETIME,
    EndDate DATETIME,
    IsActive BIT
);

-- ==============================================
-- 2. BẢNG PHỤ THUỘC LEVEL 1 
-- ==============================================
CREATE TABLE Users (
    Id INT PRIMARY KEY IDENTITY(1,1),
    RoleId INT FOREIGN KEY REFERENCES Roles(Id),
    Username NVARCHAR(100),
    PasswordHash NVARCHAR(255),
    Email NVARCHAR(100),
    AuthProvider NVARCHAR(50),
    CreatedAt DATETIME,
    IsActive BIT
);

CREATE TABLE Authors (
    Id INT PRIMARY KEY IDENTITY(1,1),
    FullName NVARCHAR(255) NOT NULL,
    Biography NVARCHAR(MAX),
    CreatedAt DATETIME DEFAULT GETDATE()
);

CREATE TABLE Publishers (
    Id INT PRIMARY KEY IDENTITY(1,1),
    Name NVARCHAR(255) NOT NULL,
    Address NVARCHAR(500),
    CreatedAt DATETIME DEFAULT GETDATE()
);

CREATE TABLE Brands (
    Id INT PRIMARY KEY IDENTITY(1,1),
    Name NVARCHAR(255) NOT NULL,
    OriginCountry NVARCHAR(100),
    CreatedAt DATETIME DEFAULT GETDATE()
);

CREATE TABLE Books (
    ProductId INT PRIMARY KEY,
    AuthorId INT FOREIGN KEY REFERENCES Authors(Id),
    PublisherId INT FOREIGN KEY REFERENCES Publishers(Id),
    Translator NVARCHAR(255),
    PublicationYear INT,
    NumberOfPages INT,
    CoverType NVARCHAR(50),
    Language NVARCHAR(100) DEFAULT N'Tiếng Việt',
    Weight DECIMAL(10,2),
    Dimensions NVARCHAR(100),
    FOREIGN KEY (ProductId) REFERENCES Products(Id) ON DELETE CASCADE
);

CREATE TABLE Stationeries (
    ProductId INT PRIMARY KEY,
    BrandId INT FOREIGN KEY REFERENCES Brands(Id),
    Origin NVARCHAR(100),
    Material NVARCHAR(255),
    Color NVARCHAR(100),
    Weight DECIMAL(10,2),
    Dimensions NVARCHAR(100),
    Specifications NVARCHAR(MAX),
    Warning NVARCHAR(500),
    FOREIGN KEY (ProductId) REFERENCES Products(Id) ON DELETE CASCADE
);


-- ==============================================
-- 3. BẢNG PHỤ THUỘC LEVEL 2 (Tham chiếu Users & Products)
-- ==============================================
CREATE TABLE UserProfiles (
    Id INT PRIMARY KEY IDENTITY(1,1),
    UserId INT FOREIGN KEY REFERENCES Users(Id),
    FullName NVARCHAR(100),
    Phone NVARCHAR(20),
    Address NVARCHAR(MAX),
    AvatarUrl NVARCHAR(255)
);

CREATE TABLE Inventory (
    Id INT PRIMARY KEY IDENTITY(1,1),
    ProductId INT FOREIGN KEY REFERENCES Products(Id),
    QuantityInStock INT,
    WarehouseLocation NVARCHAR(100),
    LastUpdated DATETIME
);

CREATE TABLE StockTransactions (
    Id INT PRIMARY KEY IDENTITY(1,1),
    ProductId INT FOREIGN KEY REFERENCES Products(Id),
    HandledByUserId INT FOREIGN KEY REFERENCES Users(Id),
    SupplierId INT FOREIGN KEY REFERENCES Suppliers(Id),
    TransactionType NVARCHAR(20),
    Quantity INT,
    TransactionDate DATETIME
);

CREATE TABLE Carts (
    Id INT PRIMARY KEY IDENTITY(1,1),
    UserId INT FOREIGN KEY REFERENCES Users(Id),
    SessionId NVARCHAR(255),
    CreatedAt DATETIME
);

CREATE TABLE Orders (
    Id INT PRIMARY KEY IDENTITY(1,1),
    UserId INT FOREIGN KEY REFERENCES Users(Id),
    DiscountId INT FOREIGN KEY REFERENCES Discounts(Id),
    ProcessedByUserId INT FOREIGN KEY REFERENCES Users(Id), -- Thêm dấu vết Sale Staff
    TotalAmount DECIMAL(18,2),
    Status NVARCHAR(50),
    ShippingAddress NVARCHAR(MAX),
    CreatedAt DATETIME DEFAULT GETDATE()
);

CREATE TABLE SupportRequests (
    Id INT PRIMARY KEY IDENTITY(1,1),
    UserId INT FOREIGN KEY REFERENCES Users(Id),
    HandledByUserId INT FOREIGN KEY REFERENCES Users(Id), -- Thêm dấu vết CS Staff
    Subject NVARCHAR(255),
    Message NVARCHAR(MAX),
    Status NVARCHAR(50),
    CreatedAt DATETIME DEFAULT GETDATE()
);

-- ==============================================
-- 4. BẢNG PHỤ THUỘC LEVEL 3 (Tham chiếu Order & Cart)
-- ==============================================
CREATE TABLE CartItems (
    Id INT PRIMARY KEY IDENTITY(1,1),
    CartId INT FOREIGN KEY REFERENCES Carts(Id),
    ProductId INT FOREIGN KEY REFERENCES Products(Id),
    Quantity INT,
    AddedAt DATETIME
);

CREATE TABLE OrderItems (
    Id INT PRIMARY KEY IDENTITY(1,1),
    OrderId INT FOREIGN KEY REFERENCES Orders(Id),
    ProductId INT FOREIGN KEY REFERENCES Products(Id),
    Quantity INT,
    UnitPrice DECIMAL(18,2),
    SubTotal DECIMAL(18,2)
);

Class
📦 MODULE 1: AUTHENTICATION & USER (Quản lý Tài khoản)
1. Class User Thực hiện các thao tác liên quan đến bảo mật và trạng thái tài khoản.
boolean login(String rawPassword): Kiểm tra mật khẩu nhập vào có khớp với passwordHash không (dùng BCrypt).
void changePassword(String oldPassword, String newPassword): Đổi mật khẩu.
void lockAccount(): Khóa tài khoản (set isActive = false).
void unlockAccount(): Mở khóa tài khoản.
boolean hasRole(String roleName): Kiểm tra user có quyền cụ thể không.

💡 LỜI KHUYÊN KIẾN TRÚC TỪ SENIOR: "Fat Model, Skinny Service"
Trong Spring Boot, các bạn sinh viên rất hay mắc lỗi Anemic Domain Model (Mô hình miền thiếu máu) — tức là vứt toàn bộ code tính toán vào các class xxxService.java, còn các class Entity chỉ toàn get/set ngu ngốc.
Với danh sách Method trên, tôi khuyên nhóm bạn áp dụng tư duy "Fat Model, Skinny Service":
Trong Entity (Order.java, Cart.java): Đặt các hàm xử lý logic nội tại như calculateTotal(), applyDiscount(), increaseStock().
Trong Service (OrderService.java): Chỉ làm nhiệm vụ điều phối (Orchestration). Ví dụ:Java
@Transactional
public void checkout(Long cartId) {
    Cart cart = cartRepository.findById(cartId);
    Order order = new Order();
    // ... copy items từ cart sang order ...
    order.calculateTotal(); 
    orderRepository.save(order);
    cart.clearCart(); // Logic tự dọn dẹp nằm trong Entity Cart
}
